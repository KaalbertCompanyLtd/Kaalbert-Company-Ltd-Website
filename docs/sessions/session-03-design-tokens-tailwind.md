## Architecture constraints
- ADR 0010 (must follow exactly): shadcn/ui generated **on Base UI, not Radix** — Base UI
  became shadcn's default primitive library in July 2026; Radix is still supported but is
  not this project's choice. Lucide (`lucide-react`) for icons — shadcn's own default icon
  set, not a different icon library.
- The shadcn CLI copies component source directly into the codebase (typically
  `components/ui/`) — the team owns and can edit every generated file. This is itself the
  mechanism that satisfies ADR 0001 ("packages as building blocks inside hand-built UI,
  never a product that owns the interface"): shadcn is a code generator invoked once per
  component, not a library the app depends on or that owns any route/data model, so no
  `no-restricted-imports` ESLint concern applies to it the way it would for a real CMS/
  admin-kit package.
- Every generated component must resolve its colours/radii from the T1.3 token layer with
  **no per-component recolouring** — `ui/design-system.md` states the token structure is
  designed so `bg-primary`, `text-muted-foreground`, `border-border` etc. already resolve to
  Kaalbert's palette out of the box. If a generated component's default classes don't pick
  up the brand palette correctly, that's a signal the token names in `app/globals.css` don't
  match what the shadcn CLI emitted — fix the mismatch, don't hand-patch colours onto the
  component.
- Base UI supplies the accessible behaviour (focus management, keyboard navigation, ARIA
  roles) — do not hand-build any of that; use the primitive as generated for anything
